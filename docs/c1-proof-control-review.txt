   A certificate discarded earlier may not be required by a surviving owner

F. Current PMP/VM epoch, raw external translation flush, privilege, owner

   inert queued/inflight/unbound results earlier. Compare architectural traces,

4. If a FULL cache-to-bank-state cut is later required

The smallest coherent boundary is a set of changes, not one delayed clear bit:
(i) Q for the two speculative stop ports;
(ii) cause-specific lifecycle events captured BEFORE row matching/reduction;
(iii) remove or factor any remaining busy-dependent bind/consume permission
feedback, with exact same-cycle final permission preserved;
(iv) retain raw recovery/context veto at the real authority boundary and prove
that inert stale storage cannot issue, bind or publish usable authority.

For (ii), commit events identify OLD full tokens; rename events identify NEW
replacement tokens and clear a row at that index only when the old row token
differs, or explicitly snapshot the old token. consume identifies the exact
real-capture token. Never register an index-only clear. Apply matching after
the register and deny reuse from anticipated clears; admission uses pre-edge
free rows. New allocation must not be cleared by an old event.

For accepted recovery, either preserve a proved row-lifetime/owner-generation
law with captured boundary/head, or capture row-token/nonfree identity so a
deferred age/boundary decision cannot clear a reused row. A captured boundary
without old head (or an equivalent invariant) is not a complete payload.

State estimates are alternative DESIGN BUDGETS, not synthesized resources:
  Q-only candidate: 0 bits.
  Earlier compact C1 estimate: 452..484 bits, CONDITIONAL on lifetime laws and
    event encoding; not a validated drop-in queue.
  Explicit conservative design: 5 event slots x (68 token+valid)=345 bits;
    recovery token68+old-head4+inclusive+valid+clear-all=75;
    context epoch32+valid+cancel-unbound=34;
    3 shared row identity snapshots x (68 token+nonfree)=207;
    total 661 bits, before any additional necessary descriptor/incarnation
    or bind-offer staging. Snapshots are captured unconditionally by slot,
    not selected using a late per-row clear. This budget alone does NOT solve
    (iii). If its lifetime premise fails, enlarge/redesign it and re-review.

For (iii), first test algebraic domination of head-system/trap controls by
earlier current-owner/raw-intent vetoes; do not alter architectural system
start/drain acceptance. If retaining original LSU permission, accept that its
bind/consume CE path remains and label the result a partial cut. A delayed
bind needs a separately proved pin reservation: without it an unbound row can
be evicted before delayed binding. Do not introduce an unqualified RegNext.

Simultaneous-event law, required before implementation:
  - Accepted cancellation/replacement/real consume invalidates only its exact
    old owner; it dominates old-result publication and old-owner binding.
  - Raw recovery or context veto denies new authority on the CURRENT edge;
    architectural recovery priority remains the ledger's existing rule.
  - Ledger priority remains head trap, then accepted head system unless an
    authorized external head tie wins, then its existing ordinary arbiter.
    Repeated nonaccepted system requests are not new accepted events.
  - An earlier pending event cannot clear a newly allocated row/owner.
  - Same-edge bind versus eviction needs an explicit winner and independent
    check. Existing eviction tests pre-edge !bound; do not assume that newly
    asserted bind automatically excludes eviction. Either prohibit the overlap
    with a proved offer law or make binding pin the exact row on that edge.
  - A surviving bound STORE cannot be dropped on epoch change or lack of proof
    owner match. Descriptor immutability must be asserted independently;
    ownerGone alone is not proof of authorized cancellation.

6.1 Store lifetime argument and its precise scope

PendingStoreProofRobOwner.connect requires pending && memoryLive &&
addressKnown, exact indexed full token, and ordinary STORE class. After a real
LSU start, IntegerBackend:1727 clears that owner's pending at the edge. Killed
owners clear pending/memoryLive at :705 onward. Rename publishes a new full
token at :2903 onward. Therefore the existing row ownerMatches is false in
the following cycle after one of those events, without same-cycle accepted
kill/commit/rename/consume going into the bank. Row storage may free one edge
later, while row proof.valid already becomes false from current ownerMatches.

For a retained STORE certificate, ALU operand enqueue at :2542 is not itself
a counterexample: those stages assert non-memory class at :2550. Store address
preparation is excluded from ordinary ROB completion at :2642-2647. Still add
an independent STORE lifetime assertion: any loss/change of its pending owner
must be exact actual STORE capture with frozen obligation transfer, authorized
kill/replacement, or another explicitly identified architectural termination.
A descriptor mismatch alone must not silently justify releasing a bound row.

Remove late clear/consume not just from final cleanup, but from every store-row
admission, queued selection, selectedValid, queryOwnerLive, translatedRowLive,
result publication and bind guard. Current full owner/descriptor/epoch checks
must remain. A killed/consumed descriptor may be captured into inert storage
on that edge; after the edge it must have no authority. Bind/real start is
blocked on the original current recovery/context boundary. Never borrow a row
being cleared: only pre-edge free rows admit. Test the delayed presentOwners
occupancy and requery cost; 0 new state is not 0 cycle/area cost.

6.2 A missing part of a store-only edit: the load certificate

The bank also uses clearOwners/consume in load selection/result capture and
loadValid cleanup (PendingVirtualStoreProof:156,207,266-278). Retaining these
keeps accepted-control -> loadValid D/CE paths, even if store state CE is cut.
The intrinsic/candidate valid output still reads loadValid, so the existing
flush-valid split does not solve its register input cone.

Do not simply keep a never-expiring old load certificate and assume a 64-bit
token can never be reused. For a zero-new-state implementation, one possible
local lifetime guard is the EXISTING registered resident load candidate:
invalidate the stored certificate when its exact current load candidate is
absent or full token/VA/size does not match; gate a newly arriving certificate
with the corresponding incoming descriptor-to-current-candidate check. A
result for a different candidate remains inert or is discarded/requeried.
No new state is needed, but this changes retention behavior and must be measured.

Next-state priority matters: appending `when(!oldStoredMatch) {loadValid:=false}`
after fresh-result capture can erase a GOOD first result because the OLD record
does not match yet. Define incoming-result validation and old-record invalidation
separately. Prove current resident/full-token/epoch/PMP checks at final authority,
including same-edge kill/consume, and keep the legacy bank behavior off-switch.
This is a design option, not an implemented or proven load-certificate rule.

6.3 Specialized ordinary parallel LOAD capacity

ParallelLoadStoreUnit:185-204's generic candidate capacity contains boundOffer
(:193), which depends on boundHeadStoreOverlapCommon and live start payload's
frozen/canonical-store epoch. It is unsuitable as the independent bind source.
For this dedicated use, fix parallel=true, ordinaryPrechecked=true and
boundStoreOffer=false AT ELABORATION. Retain exact registered serial-store
exemption (full relaxStoreOwner token, requestAccepted, certifiedStoreClass),
completion selection, handoff-to-empty-slot and cancelled-slot exclusion.

Algebraic specialization of the current selector:
  exempt_i = relaxStoreOwner.valid && busy_i && !parallel_i &&
             requestAccepted_i && certifiedStoreClass_i && fullOwnerMatch_i
  handoff = canonicalHandoff && anyEmpty && anyExempt
  selected = handoff ? firstEmpty : completionValid ? completionChosen : firstEmpty
  capacity = (completionValid || anyEmpty) &&
             AND_i(!busy_i || parallel_i ||
                   (completionValid && selected==i) || exempt_i)
No bound-store offer or othersIdle term survives in the specialized formula.
Do not replace it with merely anyEmpty or any nonserial slot. Real slot
selection must match as well as the Boolean capacity.

A concrete GENERAL-component counterexample: no empty slots, selected slot
done/not-cancelled, completion valid but completion output READY=0. The formula
reports capacity, while LoadStoreUnit:146 has start.ready=0. Binding on that
capacity alone would pin a row for an unaccepted load. Current IntegerBackend
:1805 sets lsu.complete.ready=true and :1605 asserts committed offers are
always captured. These are explicit integration restrictions, not a general
Decoupled law. Add a negative stalled-completion fixture and reject the candidate
outside this topology. Preserve chosen slot equality and parent/child fire equality.

CanonicalStoreTracker.certificate.valid (:118-119) reads registered tracking,
current ownerLive/stable and epoch; it does NOT directly contain invalidate.
Thus retain the exact current exemption where lawful. Its invalidate still
updates tracker state next edge; do not bypass ownerLive or stable to gain capacity.

6.4 Exact early bind law, not a prediction or reservation

Construct an independent ordinary nonhead prechecked-LOAD offer from the current

Also assert exact load token, selected physical slot, credit reserve/consume

6.5 Same-edge bind/evict: useful conditional proof, not assumed away

In the current active backend, a true early bypass requires a live proved row
for EVERY older pending STORE. The bank query mask targets those same older
eligible stores missing from presentOwners. If both sets use exactly the SAME
current load candidate and no policy exception exists, bind implies queryMask=0,
therefore no admission/eviction on that edge. This can avoid extra pin state.
Prove this with an independent all-older-store oracle and assert it explicitly.

A standalone bank can easily be driven with bind on an unbound proved victim
and a separate missing older store query. Its existing eviction sees pre-edge
!bound and later cleanup overrides bind. This is a valid COMPONENT overlap,
not yet an established reachable backend counterexample. If the proposed
early offer changes query candidate timing, or the above set equality fails,
the overlap becomes unsafe. Either retain/prove exclusion or explicitly make
same-edge binding pin that exact row; do not suppress the check.

- Structural cone audit must inspect ALL bank state/query/load/bound/records

Verdict: no reachable full-profile architectural counterexample established
