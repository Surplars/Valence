# Shared I1/A1 platform candidate

`CommonMachinePlatform(CommonCpuProfile.named("i1" | "a1"))` selects only the
CPU-domain tile. The fabric, 128 KiB ROM, timer, APLIC, copy DMA, packet DMA,
JTAG loader, CMU and managed 10/100/1000 MAC/UART are instantiated once outside
that choice. Both profiles keep private 32 KiB I/D caches and two ways. I1 keeps
the batch44 CPU features and explicitly adds banked 16-entry TLBs, precise AIA
CSR access and acknowledged FENCE.I. A1 starts from public `Selected`, adding
its existing internal whole-line return; no unpublished CPU candidate is used.

## Initial targets, not physical qualification

| CPU | CPU | fabric | mtime timebase | DDR UI | UART/AON |
| --- | --- | --- | --- | --- | --- |
| I1 | 300 MHz | 250 MHz | 250 MHz | 250 MHz | 50 MHz |
| A1 | 100 MHz | 250 MHz | 250 MHz | 250 MHz | 50 MHz |

CPU/fabric use independent clocks and depth-16 Held-II1 queues. Full TL A/B/C/D/E,
independent whole-line grants, two native owner lanes, MSI and maintenance epochs
retain identity and real response completion. The Home has two clients, 1024
tracked lines/four ways and two acquisition/two writeback contexts. The DDR
manager keeps four outstanding slots/two write credits. FIFO emptiness is not a
Home drain acknowledgement. No clock gating or one-sided reset of CPU/fabric is
supported; `bootEnable` is a latched cold-start admission only.

The shared ROM is 69,568 bytes in the 131,072-byte physical capacity. Its SHA256
is `9b7b73d044f0c6a457f5ed7c3ae2f332aa3b076d26ddf65bef577fe24278e80d`.
`fpga/firmware/build.py --common-platform` keeps CPU100/CPU300 inputs byte-identical.
`rdtime` conversions use 250 MHz; CMU resource 1 supplies runtime nominal CPU Hz.
TIME resource 2 is independent of CPU. UART/network control timing uses the
actual fabric rate rather than CPU metadata. Existing CMU resource indices and
its 65,536-cycle timeout are preserved.

## Maintenance and downloads

CPU FENCE.I drains old fetches/private dirty data, submits an epoch, waits for
real Home/native/DDR/transport completion, then invalidates instruction state and
retires. Protocol completion traffic, including a reservation clear generated by
a late probe, continues during drain. The current boot-only JTAG loader retains
its existing arm/write/CRC/claim protocol through coherent shared DMA; it is not
a general CPU debugger. The separate external hot-maintenance command remains
unaccepted until an independent precise halt contract is implemented.

## Evidence and remaining gates

- Both full CPU tiles, the complete boundary and both assembled platform choices
  pass Scala elaboration. Old default constructors retain their behavior.
- Scalar directed test reaches 16 real owners and II1 request/response windows;
  clear ordering, response backpressure and corrupted-owner negative pass.
- Shared fabric r6 passes 55 scalar requests, 11 ROM reads, 27 real DDR write
  responses, 16 DMA words and two maintenance epochs. A late probe reservation
  clear after tile-ready is explicitly covered. No acceptance-only write ack.
- Common ROM explicitly returns both physical banks of the containing 64-bit beat
  for the I1 fetch-span contract. Request size, denied-range checks and requested
  bank errors remain unchanged. The independent ROM fixture checks 22 replies,
  six denied accesses and 88 held responses, plus misalignment/mask assertion
  negatives. The original adapter default still selects a single bank. Extra
  returned bytes confer no execution permission: the CPU still checks full-word
  PMP and fetchSpan/parcel validity independently.
- Both production exporters pass with hardware clocks, full geometry, no program
  ports and the 128 KiB Vivado ROM IP. Scalar arbitration maps to five syntactic
  LUT/carry-cell levels on its ready output; this is a structural check, not STA.
  The restored two-slot Atomic-to-Home registered cut retains multiple owners.
- Both full-capacity CPU profiles pass the same independent-clock native guest:
  exact `COMMON\r\n`, 11 DDR reads, nine writes/nine real B responses, three
  FENCE.I completions, one timer and one APLIC/IMSIC interrupt, and dirty code
  refetch returning 9 then 42. The UART-wait-heavy guest takes 52,185 I1 CPU
  edges or 17,493 A1 edges at different CPU rates; these are not an IPC or CPU
  speed comparison. Maximum observed read concurrency is one in this guest;
  the separate Home/bridge fixtures qualify retained multi-owner capacity.
- The first-client1 Home/MSI arbitration now has deterministic reset and one
  shared valid/payload/ready selection. Native four-state positive tests retain
  fair II1; the original uninitialized-RR form is an exact failing negative.
  Home tests also cover delayed/reversed E and same-edge sink release/reuse.
- Both profiles also pass the unmodified full 69,568-byte shared ROM's native
  data/BSS initialization and exact 53-byte startup line, with all 32,768 ROM
  words programmed and unchanged UART ratio. I1 reaches 56,969 retirements and
  A1 49,040; these include polling and are not performance comparisons. Both
  runs use the same VVP as the short guest, with source/class hashes unchanged.
  I1's nominal 300 MHz is represented as a 3334 ps period (about 299.940 MHz at
  1 ps precision), A1 as 10000 ps, fabric/timebase as 4000 ps and UART/AON as
  20000 ps. No absolute-frequency scaling or UART acceleration is used.
  This is startup-line coverage, not full TUI/network or physical board boot.
- The assembly exposes AXI, DMI and tri-speed RGMII edge ports. FPGA pins,
  BSCAN65/USER2, MMCM/MIG and final constraints belong to the board wrapper.
  Routed setup/hold/pulse-width, RX, reset, CDC and bus-skew signoff remain required.

Native export is explicit, never the old small I1 test profile:

```
java -Dchisel.project.root="$PWD" -cp "$CLASSPATH" platform.CommonMachinePlatformMain \
  FRESH_OUTPUT i1 --programmable --compile-receipt=SUCCESSFUL_COMPILE_RECEIPT.json
```

Use `a1` for the other CPU. The exporter binds source, compiled classpath and RTL
hashes. Production export uses `--vivado-memories` instead of `--programmable` and
requires the same full ROM COE in the board package. The board package separately retains the original ROM and its zero-filled
128 KiB image (`c37ecf00a4864b537c6d8a804a2207289bbde9226ba247c1ead4dcad733a365f`).
The firmware contract proves their byte identity and reads nominal CPU Hz from
CMU resource 1 at `0x10080148`; CPU metadata never substitutes for timebase Hz.
Hardware clock buffers remain
present in native RTL; any digital primitive model is simulation-only evidence.
A1 uses normal packed SystemVerilog because firtool cannot flatten one public
fetch mux under disallowPackedArrays. Its native Icarus flow converts with the
installed sv2v and binds both original and converted hashes; the board flow uses
the original SystemVerilog.
