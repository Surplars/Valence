# Exercised decoded-request contract

This direct-backend fixture supplies abstract decoded requests. It does not execute its metadata instruction words through the frontend. The instruction class, opcode and active control semantics must nevertheless agree with ordinary RV64 operations. Architectural register numbers, full 64-bit immediate addresses and expected PC/instruction retirement provenance are authored independently. The load/store/add metadata words are intentionally minimal class witnesses, not bit-accurate encodings of those abstract operands.

## Confirmed active-field defect and correction

`IntegerDecode.scala:163` makes an ordinary store use a register second operand (`useImmediate=false`). The original host drove `!divide`, giving stores `true`. In the production shared preparation scheduler, `source2Ready` includes `request.useImmediate`; therefore the incorrect host field can repeatedly make an already-address-known, data-unready store eligible. This is a host-stimulus decode mismatch. The preserved overlap failure is not evidence that a real decoder-generated workload has that scheduler behavior.

The corrected overlay changes only the driven `useImmediate` value for ordinary stores. It retains all original program ordering, addresses, 300-cycle ordinary response delay, actual cache/TL overlap requirement, independent data and retirement checks, and late-fault expectations. Its `--inject-store-decode` control restores the old true pattern and must fail before the request is submitted, with `ordinary store decode requires register rs2 dependency (useImmediate=false)`.

For every class, the driver sets atomicOp=0, predictedNextPc.valid=false, fetchFault=false, fetchPageFault=false and fetchTval=0. Those values agree with the exercised ordinary, non-faulting cases. ExpandedInstruction equals the metadata instruction, which is essential for the real CSR execution and DIV class.

The host unconditionally drives memorySize=3, including non-memory add/DIV/CSR requests; the real decoder drives 0 for non-memory instructions. This field is inactive for those requests and does not select memory execution. Likewise, ignored immediate values on DIV and CSR differ from literal decoder extraction. These differences are disclosed and were retained so that the corrected rerun isolates the functional store-field change. No other active request-control mismatch was found in the five exercised classes.

This review does not qualify atomics, branches, floating-point instructions, instruction decoding, fetch, or arbitrary other direct-backend request combinations. The production frontier query eligibility question is separate: the existing rank-1 AGU can use a saved store address or a registered-ready rs1 plus immediate without reading rs2, but that possible RTL change must not be justified by this malformed-host failure.
