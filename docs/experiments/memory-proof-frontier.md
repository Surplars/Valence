# Bounded memory proof frontier prototype

Current integration status and exact opt-in commands: [source checkpoint](frontier-lru-opt-in.md). Initial-checkpoint statements below retain their historical scope.

Status: source-only prototype, uncompiled and unqualified at initial checkpoint. Default OFF. No performance, FPGA resource/timing, or board result is claimed. Published development/main and archived source/model receipts are unchanged.

The reviewed source control is cdf10665ff98ce51c11e171cbe6471bb545d9a4a with the exact model-r64p64-r1/profile.json baseline. The only new treatment is memoryProofFrontier (the approved fourth selected metadata-read budget deviation is detailed in memory-proof-frontier-ports.md), enabled explicitly by --memory-proof-frontier. Supported integration is the reviewed ROB64/PRF64/LSU4 two-issue staged Sv39 profile with 16 proof rows and real cache geometry 256 sets, 64-byte lines, two ways and the existing two MSHRs/two response/two WB entries. No recommended preset enables this option.

MemoryProofFrontier reserves one of sixteen credits before its AGU capture. One selected read/write TLB peek and one physical PMP pipeline validate complete ordinary RAM proofs. The query path owns existing ranked memory-preparation port 1 exclusively in ON; rank 0 retains the original staged path. This changes original-path preparation throughput and adds registered bank lookup latency, which must be measured with genuine Sv39 warm-hit traffic, as well as original Bare case0. No new third AGU/PRF immediate path is added. Store address queries use saved address metadata without waiting for rs2.

The inverse ROB directory stores a row index and present/positive bits. Independent row token/epoch state is immutable until removal; 16 functional full-token consume comparisons are real hardware costs. One logical payload Mem read is arbitrated for original/head lookup, frontier candidate fetch and sequential sixteen-row coverage. One logical write captures each positive result. The selected cache includes its row identity, and any loss/reuse invalidates the cached authority. The internal READY grant keeps sticky snapshot invalidation; its four current-set comparisons are repeated at actual grant via a shared address selection, including LSU slot replacement. Only the added frontier route sees this conservative set deferral.

Actual original/head priority and data-ready head drain suppress younger frontier grants. Unconditional LSU completion acceptance is preserved and start.valid implies start.ready is asserted in the backend. A younger start binds every retained pending proof it relied on. Loads transfer the current frozen PA into the actual operation and physical load-order replay metadata before releasing their row. Head stores retain original VA/virtualized class and carry the frozen payload beside their full-token/epoch origin through every actual request boundary. The adapter never retranslates a frozen store and only creates canonical authority at its existing physical checked acceptance after current write PMP, epoch, class, shape and full-range checks. No early store acknowledgement is introduced.

Control selectors, directory clear logic, dynamic result-validation metadata, token compares and range/PMP logic are additional costs.

Required gates are frozen in the reviewed VERIFICATION.md, including real write-key hit-only service, cancellation in every pipeline stage, all-route frozen consumption, preserved prefix recovery, READY dependency/line changes, alias/replay, held request/cancel-drain, real frozen store late errors, and a controlled A/eight stores/seven older pending loads/C witness. Success requires C's actual cache and external ordinary-demand acceptance before A's first response; a proof or LSU start alone is insufficient. Original case21 and later warm case0/Sv39 case6 use unchanged guest semantics and host DDR32/gap1/AW-blocks-R only after the coordinator authorizes each runtime gate. Case6 needs its own exact host contract. No broad regression, capacity matrix, synthesis or publication is implied.
