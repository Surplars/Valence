# GSIM reset-release observation and independent native check

The original driver called `set_reset(true); step()` twice, then `set_reset(false); step()`, while its independent model reset VM history to zero at each held-reset call. The generated GSIM `step()` calls `resetAll()` first and then its combinational/state-update `subStep` functions. `resetAll()` clears Q and NEXT, but the subsequent settle recomputes unconditionally sampled VM-history NEXT to machine privilege M=3 even with reset still asserted. The first deasserted step consumes that prepared NEXT. At observed cycle 3 both fallback and published adapters reported total change=0, although the independent expected reset VM mismatch was 1. The raw PMP event remained zero and the paired differential comparison agreed. Original failure and diagnostic expanded values are preserved.

The driver correction calls the generated public `resetAll()` once more at the end of each held-reset step, keeping the asserted reset effective through settle. It neither changes generated RTL nor writes individual DUT state. Independent oracle expectations remain unchanged. After this correction the 8-entry real CSR/paired adapter diagnostic passed 18,768 CSR/phase checks, including 204 raw PMP events and 270 total context changes. A later new memory-driver timeout was separately diagnosed: the adapter has no physical-response-data buffer, so physical response READY intentionally follows the upstream response READY. The test had incorrectly waited for physical acceptance while holding the upstream sink not ready. Corrected traffic keeps response VALID/data asserted through the held upstream response and consumes both at the shared handshake. It passes 19,119 total paired checks, 19 accepted requests, 17 physical requests and 18 responses; one request is intentionally canceled by common reset and one stale certificate faults without a physical request.

Native cross-check used the exact same already-generated real 8/live FIR and pinned firtool 1.135.0. Existing Icarus required the supported output-style option `disallowLocalVariables`; no RTL was hand-edited. The emitted real CSR and both real adapters pass 29 edge checks. During held reset and after reset deassertion before the first clock edge, total change is 1 because live privilege is M=3 and previous VM privilege is 0. The first released edge consumes that change and increments both epochs. An OFF address write raises the raw event and both total-change outputs immediately after its write edge; epochs increment only at the following edge. Same-value writes, reserved-bit filtered no-ops, own-lock ignored addresses and locked cfg writes do not raise a raw event. Reset and repeat are covered.

The older registered-PMP-region qualification used the original reset driver, but it had no DataTranslationAdapter or VM-history/epoch consumer. Its covered raw CSR reset state, decoded ranges, permissions and CSR sequencing are unchanged by this observation. It did not qualify this newly tested CSR-to-adapter initial VM mismatch. The new boundary gate and native edge cross-check close that additional boundary; this is not a blanket invalidation of earlier range/CSR tests.

Current production seven-file patch remains SHA256 09e953dd362e4fa60ef9f3bf6cdb6d05a45bb20fa6c11320f1ab6b1f1d01fe22. The latest test fixture additionally compares payload only when VALID, while always comparing VALID, READY, epoch/stability/context signals; it poisons only the candidate's invalid request payload so undefined payloads cannot create a false equivalence requirement. That refinement needs a fresh frozen run and is not attributed to the earlier diagnostic/native fixture bytes.
