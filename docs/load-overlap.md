# 普通RAM读取与已发出写重叠

实现前合同：当所有缓冲写均已按序发往外部端口，而响应尚未全部返回时，允许与剩余写无字节重叠的
普通RAM load发出。复用已有按字节覆盖位图，不添加地址预测或重放。存在完整覆盖仍走原本地转发，
部分覆盖仍等相关写消失后重新判断；MMIO和所有非指定RAM访问仍等待count=0。

保持外部请求中的旧写先于新load、响应按请求顺序返回。不依赖“写在接受时立即生效”：
新load与未完成写的字节集合必须不相交。相同64位beat内不同字节也允许；适配器必须保留byte mask语义。
增加门控只读取寄存count/issued和原覆盖位图，容量、端口宽度和响应队列均不变，目标请求II仍为1。
外部读响应排在旧写响应后，提前请求的收益取决于从设备是否支持在途请求重叠，而不是保证乱序完成。

保持上游读响应顺序：reads不为0时禁止本地写确认/本地转发越过旧读；新的RAM写也因此不能越过读取。
满覆盖转发、部分覆盖、同beat不相交字节、延迟及零延迟、读/写背压、MMIO排空和busy均需独立验证。
GSIM独立软件模型按请求集合检测早读，要求所有旧写已发出、未响应字节与读掩码不交叠。
实际Fmax、面积以及DDR表现未测；这是当前有序DataPort边界下的保守并行化。

## 独立验证

1/2/4/8项缓冲各3个种子、延迟和零延迟两种模式，每次3,011项事务。
延迟模型仅在写响应被消费时应用对应的byte mask到物理RAM，读值不假设旧写已提前落地。
默认容量的三组延迟测试观察888/940/912次提前读，其中同beat不相交字节11/24/26次；
部分覆盖的读、非RAM请求不得提前，最终物理/架构RAM一致。错误写响应和篡改读值的负向注入通过。

整核软件模型把原“全部事务最多4笔”拆成读最多4、写最多4、总响应信用最多5；硬件队列本来就是
memoryEntries+1项，没有扩容。纯load仍检查最多4项并行。默认C程序额外断言存在读写响应重叠。
请求/响应顺序、RAM最终值仍由独立模型/NEMU核对，未以DUT内部状态修正参考结果。

最终默认ROB32/PRF64结果：12周期RAM的C数组程序1,586→1,575周期，IPC 0.825977→0.831746；
退休后排空均为0。1/4周期RAM和其他原基准的周期不变。范围是相同程序、理想双宽取指的裸核模型，
不是同步ROM平台或实际DDR/缓存系统的性能结论。


全量 `make test` 已通过：28项Scala检查及全部GSIM/NEMU、负向注入；两种整核各278个程序、
380,406条提交。44条IPC中2条改善、42条周期不变，无周期退步。小配置ROB8的同一12周期RAM
C程序2,032→2,024周期，IPC 0.644685→0.647233；默认配置提升约0.7%，不作为普遍大幅提速宣传。
同步ROM/RAM平台记录和两套启动固件周期均不变。生产RTL已重新导出，尚未进行Vivado综合和时序验证。
