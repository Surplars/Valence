# 已就绪 load 旁路与同地址回放

默认双发射核原先总选最老的待发访存。若老 load 的地址操作数还在等待除法或另一次
load，后面地址已就绪的普通 RAM load 也无法占用空闲 LSU 槽。现在访存选择器在
待发请求中选择最老的**操作数已就绪**者；未知地址的较老 store、原子操作和系统
指令仍沿用已有年龄与串行化阻挡。非 RAM 或经过地址转换的读取不能提前发出。

同地址年轻 load 若先于老 load 发出，DMA 或另一主设备可能在两次读取间写入，
使两条 load 读到倒序的新旧值。这不符合 [RVWMO 同地址读序规则](https://docs.riscv.org/reference/isa/unpriv/rvwmo.html)。
每条已发出的 load 在 ROB 生命周期内保留 8 字节 beat 编号与 8 位字节掩码。
老 load 发出后下一拍，用寄存的 beat/掩码检查已发出的年轻 load；若字节范围
重叠，就经既有精确恢复通道从最早冲突的年轻 load 重新取指。老 load 最早也要
在该检查之后才能退休，因此多出的检查拍不会让冲突结果先退休。已发出的错误路径读排空响应，
不可撤销 store 仍只在队首执行；这个回放本身不会撤销已退休内存效果。
下游数据口还必须使按请求顺序发出的重叠读取按该顺序观察内存版本，包括外部写入。

2026-09-24 GSIM 定向证据：ROB8/PRF36 与 ROB32/PRF64 各跑除法延迟地址后的
独立年轻 load，用总线请求顺序和最多 2/4 笔在途证明旁路发生。另两组程序让
年轻 load 先读旧值，随后模型中的外部主设备写入同一 64 位地址或只重叠高 32 位，
老 load 最后才得到地址。两种配置均观察到一次回放、三次物理读取，老/年轻 load
都退休新值，逐条与独立 ISA 模型及 NEMU 对照。结果篡改注入仍被差分发现。
同地址程序另在同拍响应内存模型下复测，验证最短响应延迟时的回放边界。
这些测试验证该内存模型下的读序，不是多 hart 缓存一致性或完整 RVWMO 合规证明。

同一固定二进制的 GSIM CoreMark 单次迭代由 337,892 降至 305,375 周期，
退休指令数均为 322,780，IPC 由 0.9553 升至 1.0570，CRC 错误为 0。
零退休周期由 155,402 降至 129,473；其中队首访存请求、响应、已完成等待
分别由 26,237/40,345/42,551 降至 20,542/28,187/36,570。
CPU 物理访存请求从 74,897 增至 75,753，增加的流量在真实外部内存下可能抵消收益，
还需要带宽与仲裁对照。新增的 ROM 指令分类计数在当前 CoreMark 中观察到
56,795 条已退休 load、17,708 条已退休 store，以及 0 次由这套重叠检查触发的
load 回放；因此不能把增加的 856 笔请求归因于同地址回放。是否来自更多提前读取、
写转发变化或其他因素，还需进一步按请求归因。
这仅说明所测 GSIM 平台中的周期收益；多路就绪选择及冲突检测的 FPGA 资源、
组合路径和 Fmax 尚待 Vivado 验证。当前重叠检查已移到发射后一拍，并用 ROB 索引
保存检查对象，以去掉发射地址生成到回放仲裁的直通组合路径；是否改善实际时序仍待综合。
若频率下降抵消周期收益，须调整结构与默认配置。

当前整核回归输出 52 条裸核 IPC 记录，包含两种配置下的四项新增定向用例。
默认 4 槽的 12 拍 C 数组程序为 1,379 周期；当前 8 槽版本为 1,295 周期，
26 条同配置对照有 4 条改善、22 条不变，面积和 Fmax 仍未知。
同步 ROM/RAM 平台的同一 1,310 条 C 程序无提交背压时为 1,333 周期。
双主 TileLink 平台的 RAM、DMA、原子固件在种子 0 下
分别为 3,085/4,839/6,039 周期，均通过实际 CPU/DMA 并发回归；
这些启动周期包括平台初始化、串行等待及中断，不是计算 IPC。

复现入口：`make gsim-core-test`、`make gsim-core-memory8-test`、
`make gsim-coremark`、`make test-scala`。
裸核 IPC 额外输出 `ready_load_bypass`、`same_address_dma_replay`、
`same_address_dma_replay_zero` 和 `overlap_dma_replay`；CoreMark 报告在
`build/gsim/coremark.json`。
同步与双主平台分别由 `make gsim-platform-test` 和
`make gsim-tilelink-dual-platform-test` 验证。
