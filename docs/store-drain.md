# 写缓冲多项在途排空

实现前合同：StoreBuffer原有4项默认容量不变，仍仅提前确认显式保证成功的普通RAM写。
原实现draining布尔值把所有写响应串行化；改成独立发送指针和已发送未响应计数。
外部端口允许时连续每拍发出一项已入队写，最多min(缓冲容量,响应所有者队列容量)项在途。
响应必须按请求顺序返回，未确认项占据原槽位，保留所有字节供年轻load选择最新覆盖值。
只有响应才能释放槽位，不能因已发出而复用。未被完整覆盖的load、MMIO继续等待全部写排空。
本轮不改变分配宽度、推测RAM范围、写成功保证、中断排空和错误响应断言。

状态不变量：0<=issued<=count<=capacity；发送指针只在外部写请求握手时前进；
退休指针只在写响应握手时前进；零延迟请求与响应同拍不遗留issued。
发送选择使用独立寄存指针，不把响应ready加入请求valid组合路径。实际Fmax/面积待Vivado验证。

独立GSIM驱动须覆盖4笔写在第一项响应之前被接受、按序响应、延迟/零周期响应、总线背压、
字节转发、同拍入队/响应、指针回绕、最终RAM一致及错误响应拒绝。整核仍用独立指令模型和NEMU，
以原44条IPC与同步平台报告为对照，记录改善与退步而不只挑选最佳结果。

定向测试已在1/2/4/8项容量下通过，每项3个随机种子、延迟与零延迟两种模式，各3,009项请求。
默认4项实际观察到连续4拍发送和4笔写在途；8项配置受5项外部响应标签容量限制，实际观察5笔。
无序响应不在DataPort合同范围内，不能以此结论接入未做响应重排的外部总线。

没有通过把排空移出测量窗口来制造改善。纯load/ALU/分支/乘除等默认基准周期保持不变。
这只是指定普通RAM合同下的周期优化，不代表DDR、缓存系统性能或最高频率。
