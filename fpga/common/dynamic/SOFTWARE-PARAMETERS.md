# Bounded software clock parameters

Diagnostic candidate only. Physical parameter legality is not vendor primitive,
whole-SoC, timing, jitter, or board qualification. No bitstream authorization.

The 24-bit `program_parameters` request is `{O[7:0], M[7:0], D[7:0]}`.
The request Hz, token, fallback flag, and parameters are captured together on
`valid && ready`; subsequent input changes cannot alter the accepted operation.
The upstream MMIO owner must reject nonzero bits31:24 before narrowing to24bits.
The backend has no raw software DRP address/data/mask interface.

## Hardware envelope

- Input250MHz, DIVCLK D10, PFD25MHz.
- Integer M32..62, giving VCO800..1550MHz.
- Integer O3..128; phase0, duty0.5, fractional/fine phase disabled.
- Exact equality `25,000,000*M == Hz*O`, without rounding.
- Hz10..300MHz CPU, Hz10..250MHz fabric (`MAX_PROGRAM_HZ=250000000`).
- Cold startup and explicit fallback50 autonomously write D10/M40/O20 and all
  lock/filter words. Fallback ignores untrusted supplied parameters, but rejects
  any fallback target other than50MHz.
- Firmware initially advertises only50..150MHz in5MHz increments. The hardware
  envelope admits other exact integer solutions without changing the bitstream;
  it does not imply that every requested Hz or any frequency is timing-qualified.

DS925 MMCM limits support PFD25 and VCO800..1600 for xczu15eg-ffvb1156-2-i.
The board flow separately verifies the actual MMCM input has the unchanged4ns
DDR UI clock. A port name alone is not proof of a250MHz physical input.

## DRP and analog configuration

The primitive now explicitly uses `BANDWIDTH=LOW`, not the previous OPTIMIZED.
M63/64 are explicitly excluded: the official driver programs CP15 whereas
Vivado2025.2 requires CP12; a real M64/O128 test produced MMCME4_ADV-40 and was
rejected. We do not infer an analog hardware correction from the model. All59
five-MHz points10..300MHz remain exactly representable with M32..62. Raw table
rows63/64 are preserved in the JSON as conflict evidence, not admission.
The lock/filter characterization in `software-parameters.json` is independently
obtained by compiling AMD's five unmodified C table functions at pinned commit
acf980174aada76637ac02c1e01088f3cc7b04dd. Source URL and SHA256 are in that JSON.
XAPP888 v1.8 gives integer counter fields and reserved-bit masks. Odd M/O use
EDGE; a six-bit zero counter encodes64, allowing O128. No fractional profile is
accepted or generated; unused fractional spill fields remain at the primitive's
integer startup configuration. Only CLKOUT0 and CLKFBOUT are used by this MMCM.
AON, DDR UI, fixed MAC and debug clocks are separate resources and do not change.

The11-word RMW sequence is power27, feedback14/15, DIVCLK16, output08/09,
lock18/19/1a, filter4e/4f (hex addresses). Every full word is read back, retaining
reserved bits. The bounded serial equality check costs M+O AON cycles (maximum192)
and uses one40-bit accumulator rather than variable hardware multipliers/dividers.
Illegal input never starts DRP or newly asserts MMCM reset. Existing timeout,
late-DRDY quarantine, held-high DRDY, persistent cold-reset ownership, fatal
isolation, explicit fallback, and real gate-edge observations remain in force.

Changing VCO and LOW bandwidth changes analog lock/jitter behavior. The existing
300/250MHz performance constraints are not relaxed, but they do not qualify these
runtime analog profiles. Native UNISIM and subsequent implementation are required.

## Focused tests

`run_behavioral.py --clock-only --iverilog PATH --vvp PATH --out FRESH` runs:
original28 clock/owner checks;5 reset and2 DRDY faults; gate witnesses;
98 independent register-image/parameter cases; four ordinary-oracle negatives;
and the expanded native bench using clearly labeled behavioral stand-ins.
No Verilator is used. The golden table is not generated by a DUT function.

Native Vivado2025.2, from a fresh directory:
`vivado -mode batch -source ROOT/fpga/common/dynamic/validate_native.tcl -tclargs ROOT FRESH simulation`
Set `VALENCE_VIVADO_HOME` to the installed Vivado2025.2 directory. The same command
with final argument `synthesis` runs component OOC only, not whole-SoC signoff.
The native bench includes21 points on each lane, each roundtripping50 independently,
odd M/O, O128, CPU300/fabric250 boundaries, malformed requests, autonomous50
fallback, cold-reset restoration, pulse-width and edge/rate observations.
It must compile official UNISIM only, never `behavioral_primitives.sv`.
