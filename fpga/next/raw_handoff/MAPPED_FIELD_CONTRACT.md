## Admission and invocation

`audit_raw_handoff.tcl` defines `raw_handoff::collect CONTRACT.tcldict FRESH_REPORT_DIRECTORY`. The contract is plain Tcl dict data, read without `source` or evaluation. Run only in a fresh Vivado process, after configuring the existing `valence_mac_session::configure` with the verified Unix Python command or Windows WSL distribution/log directory. The gate reads its own checkpoint. The existing Python/WSL configuration and error-log route are reused; Windows Python and `sha256sum` are not assumed. The checker changes no design, constraints, clock properties or exceptions. Its only writes are reports and existing bridge stderr logs.

Required top-level Tcl fields:

- `schema`: exactly `raw-handoff-mapped-v1`.
- `enabled`: integer `0` or `1`, compared with fresh actual-constructor evidence.
- `binding_file`, `checkpoint_file`: bundle-relative paths, resolved relative to the contract. Keep contract, binding JSON and checkpoint in the same bundle root. No absolute/parent-relative artifact paths in the JSON manifests.
- `mac_root`, `mac_ref`: exact mapped hierarchy and REF_NAME selected from this export, reviewed before collection; no historical DCP names or wildcard root. Root must retain the source MAC boundary.
- `off_raw_clock`: required OFF, original RAW source boundary. OFF also rejects falling FDCEs on that actual RAW net under the MAC, even when helper REF_NAME/hierarchy was flattened.
- `roles`: dictionary below; required ON. OFF still verifies the full new source/export/checkpoint chain, actual mode false and helper resource absence. OFF rejects retained rawHandoff hierarchy or helper REF_NAME under the source-bound MAC root; no ON timing claims follow from OFF.

The Python admission verifier consumes JSON `fresh-mac-handoff-binding-v1` with Boolean `enabled` and exact `{path, sha256}` artifact records named `contract`, `checkpoint`, `source_manifest`, `rtl_manifest`, `constraints_manifest`, `parameters`, `actual_constructor`, `synthesis_filelist`, `provenance`. Every referenced path is inside this fresh bundle and every digest is checked before opening and again after collecting the DCP. Every manifest is a nonempty JSON object: logical artifact name → `{path, sha256}`. Source logical names use repository-relative paths. `source_expected.json` binds the current component plus entry overlay; changed source needs root review and a new snapshot, never an old certificate exception. The full source closure, actual emitted RTL/resources and all constraints must be present, including transitive includes.

The synthesis file list is normalized for this gate: one exact bundle-relative RTL artifact path per line, no comments, duplicate/blank lines or command switches. Retain the actual tool-consumed file list separately in the reviewed build evidence and demonstrate equality to the normalized list. ON includes the exact `ValenceMacRawFallingSample.sv` bytes; OFF omits that emitted resource. Source provenance includes the resource source in both modes.

`parameters` schema `mac-raw-handoff-export-parameters-v1` records actual exported Boolean `triSpeedRawClockHandoff`, integer `ingress_delay_cycles=128`, `profileFields=89`, `coreFields=172`. This is a new normalized export receipt to be emitted later, not a profile-label assertion. `actual_constructor` is the entry overlay's `actual-mac-raw-handoff.json` with schema `actual-mac-raw-handoff-platform-v1`; its actual helper presence, selected flag, widths and 89/172 fields must agree. Its existing false mapped/physical flags remain false.

`provenance` schema `fresh-mac-handoff-build-v1` requires `review=REVIEWED_SOURCE_TO_DCP`, fresh `build_id`, nonempty exact `invocation` argv, `stage` synth/postopt, Boolean `enabled`, and `<artifact>_sha256` for source_manifest, rtl_manifest, constraints_manifest, parameters, actual_constructor, checkpoint and synthesis_filelist. Fresh PAD/CDC role audit receipts must bind the same source/export/checkpoint. ## Exact ON role dictionary

All values below are exact pin NAME strings observed from the new source-bound hierarchy or freshly traced leaf graph. Lists are bit-index ascending, never lexicographic bus order. Every queried name is restored with exact escaped `get_pins/get_cells/get_nets/get_clocks` before use. Missing retained semantic pins or optimized aliases require review; do not silently replace them with guessed registers.

- `raw_clock`: original rawTxClock pin; `pad_clock`: original PAD clock boundary. `rx_clock`, `tx_clock`: original managed BUFGCE outputs. Their clocks are the same propagated RAW clock. RAW/PAD must trace directly to BUFGCE_DIV 4/2 with common REF500 input and reset, periods/waveforms 8/{0,4}, 4/{0,2}, 2/{0,1}. `rx_gate_ce`, `tx_gate_ce`: original command synchronizer outputs, with direct BUFGCE CE connections, CE_TYPE SYNC.
- `unchanged_properties`: mandatory reviewed nonempty rows `{kind exact_name property expected_value}` covering original divider/gate inversion and reset properties plus applicable clock source/master, uncertainty, latency and generated-clock properties. `kind` is cell/pin/net/clock. Use only actual properties supported by the selected Vivado version; record absent/default properties explicitly in the separate review. Never invent a property spelling or historical value. Constraint closure equality and complete exception review remain required.
- `raw_reset`: actual rawTxRelease.resetOut boundary; `rx_reset`: rxRelease.resetOut; `ingress_reset`: original ingress.release.resetOut. The existing positive CDC release audit proves each release chain; this gate proves the new CLR nets are direct and timed. It does not accept media/quiesce/epoch resets in their place.
- `ingress_delayed`: 11 original delayed output pins. `falling_rx_outputs`: the 11 source-bound falling output bits. `managed_rx_outputs`: the 11 source-bound managed RX output bits. Ordered bits are data[0:7], error[8], valid[9], byteStep[10], i.e. tuple `{byteStep, valid, error, data}`. Each output must have one direct Q driver. Ingress→falling D→managed D is checked bit-for-bit with distinct cells, 12 falling FDCE total and 11 rising FDCE total. All handoff cells are INIT0, CLR active high, CE1, no ASYNC_REG; falling IS_C_INVERTED=1, managed=0. No extra helper state, duplicate/merged bits, extra epoch, retimed CE or payload gating is admitted.

The actual Vivado property API reads `IS_INVERTED` from C and CLR pin objects; INIT remains a cell property. Do not query cell-level IS_C_INVERTED/IS_CLR_INVERTED. Collection counting/sorting may destroy their typed representation: query again immediately before property or -of_objects use. Timing-path properties are consumed before any collection count, and paths are never reconstructed from names.
- `tx_step_output`: falling sampled bit 11. `encoder_phase_and_rate_gap`: exact Q pins phase[0:6] then rateGap[0:3], positive RAW FDCE with original raw release reset and INIT0. Their complete mapped D cone must prove `(phase == 0) && (rateGap == 0)` for all 2048 valuations. Thus the decode ends before the falling FF. Additional sequential leaves, >16 logic levels, unknown primitives or optimized variable merging stop for review. Supported primitives: LUT1–6, INV, MUXF7/8/9.
- `rx_pending`: exact managed valid bit 9. `local_idle_output`: localIdle(1) semantic pin. `local_idle_inputs`: exactly [rxDrain, rx.busy, rxFifo.sourceIdle, rxStats.sourceIdle, rxConfig.destination.valid, ingress.empty, managed.valid, rxDiagnostics.sourceIdle]. The complete 8-variable equation is proved for all 256 valuations, with only the positive drain/idle inputs asserted and busy/configValid/pending deasserted permitting idle.
- `ingress_empty`: original ingress.empty semantic pin; `ingress_empty_source_d`: actual ingressEmptySource FF D, same net. `empty_launches`: every real Q startpoint of original empty's cone, from the fresh mapped graph and reviewed against original activity depth. Original128 is source/actual-export bound; this small gate does not prove all 1408 payload-delay FF transitions or the 128-bit empty reduction independently.
- `ingress_source_fanouts`: 11 ordered lists of every original delayed-bit source Q endpoint, each including its corresponding falling D. Normally each is a singleton. The sole predescribed optimization is original activity[127] sharing the delayed valid[9] FF: `reviewed_valid_activity_merge=1`, exact `ingress_activity_tail` pin on the same source Q net, that Q present in `empty_launches`, and every explicitly listed additional endpoint in the original `fanouts.empty` set. All additional pairs remain timed in the empty family. Other merges or fanout changes fail for review. Do not require the legal valid/activity shared source to drive only the falling D.
- `fanouts`: exactly keys rx_0…rx_10, tx, empty. Each value is a nonempty exact list of all actual terminal D/CE endpoints from that role: RX parser/statistics/ACK for managed RX bits, TX engine/statistics/ACK for sampled TX step, original empty→ACK and ingressEmptySource. Store every real endpoint, with a separate reviewed semantic category/source justification. Real all_fanout equality rejects omitted or additional endpoints, including a bypass. RX sinks must use the RX BUFGCE net; TX sinks TX BUFGCE; empty sinks original RAW or managed RX. Falling→managed endpoint lists are derived exact singletons; ingress source lists allow only the explicit original valid/activity sharing above.

Contract pin review must independently establish that the semantic labels match the source; supplying an arbitrary self-consistent graph is not that review. No mapped cell names or LOCs are supplied in this proposal because no fresh mapping exists.

## Timing and limits

Each real launch Q role is resolved to its owner/C for `-from` and STARTPOINT_PIN checking; ENDPOINT_PIN must equal the exact D/CE/CLR. No timing path object is serialized, indexed or reconstructed. Each pair gets separate min/max `report_timing -path_type full_clock_expanded -input_pins -file`; no redirect or `-nets`. Enumerated pairs cover 11 ingress→falling, 11 falling→managed, every managed RX and falling TX consumer, all 11 phase/rateGap launches→TX falling D, every real empty launch→every reviewed empty consumer, 12 raw-release→falling CLR and 11 rx-release→managed CLR. Nonfinite/missing/cut paths and negative slack reject; max budgets are 4 ns for half-cycle families and 8 ns for full-cycle families. Reset recovery/removal remain timed.

Min/max timing reports do not independently prove exception absence or pulse constraints. Complete exception coverage/ignored, clock interaction, pulse-width and unconstrained timing summary reports require review, along with unchanged external min/max, PAD/T1 phase and uncertainty. A passing collector deliberately returns FACTS_COLLECTED_REVIEW_REQUIRED_NOT_QUALIFIED. Run unchanged native_mac_roles.tcl for fresh selected-half PAD/T1 evidence and unchanged positive-edge CDC audits; never weaken their global FF rule. The existing 40 same-branch hold endpoints, REF500 recovery issue and original cross-branch families remain separate physical obligations.
