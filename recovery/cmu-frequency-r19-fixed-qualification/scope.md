# r19 fixed-domain epoch qualification candidate

Status: scoped final native verification PASS. Eight real-component combination cases plus four negative controls passed; the standalone helper separately passed 44 cases plus two negative controls. This is not full-system clock permission or physical qualification.

The optional CommonMachinePlatform runtimeFixedQualification parameter defaults false and requires the I1 runtime path plus real independent DDR and timebase boundaries. It observes existing transport and transaction ownership; it does not close any AW, W, AR or timer MMIO path ahead of accepted CPU/Home/DMA work. ## Ordering contract

A real accepted fabric external-maintenance command reserves the epoch in each qualifier. Only matching real fabric runtimeHeld plus allObligationsIdle and fabric-local transport emptiness permits sending that epoch to the fixed domain. DDR qualification combines existing AR-to-RLAST/AW-to-B fabric owners with all five real CDC FIFO endpoints. Fixed timer qualification uses the real MMIO bridge, including final source reply consumption. Continuous coherent time snapshots and persistent IRQ levels retain state; they are not required to become perpetually empty.

The fixed endpoint returns coherent matching-epoch true and false observations. These are delayed observations, not physical clock-gate acknowledgments. A stopped fixed clock cannot manufacture a new qualified observation or retirement receipt. Common cold reset must cover all transaction and protocol owners; unilateral reset is not supported.

Normal or canceled completion is the actual fabric terminal, not a synthetic fixture acknowledgment. After AON consumes it, old qualifier control messages and terminal/retirement receipts must actually complete before the fabric epoch retires. Initial mailbox idle is never accepted as a receipt. A cancellation before qualification still follows an explicit matching-epoch fixed-domain handshake.

The existing fabric reopens Home after the CPU has actually resumed, before AON consumes the final terminal. Therefore retirement must not demand that new post-resume CPU transactions become idle again. Live local-idle proof is used for held qualification; a historical qualified observation may establish normal decision legality only, never provide a current held or gate proof. This distinction must be exercised with resumed real CPU traffic, not only a synthetic idle toggle.

## Limits

The AXI memory endpoint in native tests remains an explicit RAM responder, not MIG or board DDR. Clock-pause tests exercise digital protocol progress, not a supported physical stop/start sequence. Timer IRQ evidence covers a persistent compare level, not capture of arbitrary transient external IRQ pulses. New helper mailbox/reset paths require physical CDC and timing qualification before any actual clock switching.

Managed peripheral control-tail integration, fixed/rate-aware MDIO/PHY timing, stopped-clock external interrupt capture, UART/CMU owner qualification, real gate feedback and official DRP remain distinct obligations. This stage must not be connected as fabricated full drain ACKs. Production default 50 MHz remains a goal separate from the unchanged CPU300/fabric250 performance implementation constraints.

`linkReady` qualifies local proof and receipt issuance; it is not a clock-presence/lock monitor or a guarantee that a previously issued receipt remains physically current. An in-flight receipt can still arrive after its source clock pauses. Production timer readiness is common-reset release; DDR readiness also requires calibration, whose loss after platform startup already demands common cold reset. Runtime link-loss recovery and physical late-lock-loss handling are not supplied by this helper. No gate may infer live-clock status from its completed control receipt.
