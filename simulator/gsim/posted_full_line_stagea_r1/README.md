# Isolated posted full-line policy: qualified Stage A

This evidence-only source package adds a default-off acquisition policy to the exact historical PostedStoreMerge owner. It does not change current production defaults or integrate the option into a CPU/cache/Home. The existing two64-byte payloads, coverage masks and sixteen-token ledger are retained. Only an independently complete64-byte mask permits a frozen permission-only decision; partial/sealed/expired collections use the data-refill contract. Recovery retains accepted obligations.

Qualified results:21 positive owner cases,6 RTL assertion negatives,5 saved-observation oracle mutations and1,350 short-policy checks. Timeout3/4 boundaries and the256-cycle owner policy pass. Default-off owner SV is raw byte-identical to historical baseline, SHA256 b1ee80f0f1188d75d330506e50506340aa57d02f6207dab2469eff05a7b3778b. Generation64 reuse is covered;2-bit exhaustion is not. The observation mutations test oracle sensitivity, not mutated RTL execution.

The fixture authors authorization, acquire and Grant/E events. It does not prove real AcquirePerm routing, coherence, zero DDR reads, safe CPU load coexistence or a speed improvement. Fatal-error tests deliberately leave accepted responsibilities outstanding. Some malformed environmental events are rejected by assertions, not a new synthesized protocol recovery mechanism.

The policy duplicates the parent context/reservation for clarity:618 extra functional metadata bits in the8-set fixture,628 at256-set geometry if integrated unchanged. No new payload/mask storage is added, but the option is not area-free. Mapping/timing and suitability of the256-cycle timeout for the real copy loop are unqualified.

All files in source/, fixtures/, host/ and baseline/ are exact tested source bytes. The helper prepare_cases.py is a separate packaging adaptation that reconstructs the frozen test's relative helper layout; only its help/dry-run path has been checked. Hardware execution through this portable packaging entry point has not been repeated. VERIFIED_OUTCOMES.json and SOURCE_HASHES.json contain relative paths only. Raw logs, absolute execution manifests and generated outputs remain in separately sealed local evidence.
